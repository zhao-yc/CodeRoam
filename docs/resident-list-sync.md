# 常驻列表与后台维护强度

每个已核验桌面实例维护最近 50 条列表摘要，并复用已有 20 条正文缓存。数量是保存窗口，不表示同时跟随全部正文。列表展示副本写入连接服务自有 SQLite 的 `thread_list_index`，仅保存会话编号、标题、项目、更新时间和排列位置；运行、审批、问答及授权不从磁盘恢复。

列表先在内存更新、推进版本并发送事件，展示索引使用固定 1500 毫秒窗口合并保存最新五十行，持续更新不会重置窗口。明确终态和正常关闭时尽力立即保存；归档删除会立即取消对应待写并清理副本，写入前仍新鲜核对可见成员，不能把已删除聊天重新写回。缓存写失败保留在线列表并在后续窗口重试；意外退出可能丢失最后一小段展示缓存，重连后从桌面索引恢复。这一延迟只适用于展示缓存，不用于任务接收、命令去重或执行回执账本；轻维护十五秒采集周期保持不变。

## 同步方式

`threads.watch` 和普通 `threads.list` 先返回索引与本代已有可信状态。未核实状态为 `unknown`，不等待原生未读或整批会话探测。显式查询归档、搜索分页或账户用量仍保留原有参数语义。

后台优先读取已核验实例管理器的活动候选；入口不可用时，仅核对发生版本变化的历史任务事件。历史只能产生候选，不能赋予实时状态或操作权限。候选探测最多两个并发，失败目标至少间隔十秒重试。静态会话不持续持有正文跟随；终态在保存展示窗口后释放内部订阅。

后台列表和正文共用已有会话连接。真实详情最多 64 个条目，纯内部条目最多 50 个，共享总上限 84；前台满额时不驱逐其他真实观看者。需要回收时优先释放最旧纯内部条目，后台满额每两秒最多轮转两个。

活动和未读的整批补偿查询有独立的两秒间隔，不随索引文件通知重复触发；文件通知仍及时刷新列表及核对发生变化的单个聊天。后台历史来源按本轮目标批量读取索引，共享一次只读连接和表结构查询，批次结束后关闭连接且不持有读取事务；每个历史文件仍核对真实路径及元数据。跨异步等待后通过 SQLite 的 `data_version` 核对外部提交，变化时重新读取本批次，避免归档或删除后使用旧成员行。该批次不跨请求保存，也不能用于交互授权，显式详情读取、成员核验及写操作继续使用新鲜检查。

正文先在内存保留当前和上一版展示窗口，完成版本计算后立即推送，不等待 SQLite。普通更新在固定 1500 毫秒窗口内合并，只保存每个聊天的最新正文；连续输出不会延后第一次保存。任务完成、失败、中断及正常关闭时立即尽力保存，终态发送失败也不影响最终窗口落盘和内部跟随释放。轻维护暂停短周期正文保存，进入前先保存，确认历史终态时仍立即保存。

正文最多保留二十条，每条展示投影不超过 512 KiB；旧版内存没有引用链。持久化在同一事务内增量保存，上一份已落盘正文由 SQL 内部保留；同版本只更新变化的来源指纹。有订阅需要续接时优先使用内存基线，必要时才读取磁盘两版，缺口退回完整窗口。写入前重新核对可见成员，归档删除立即取消待写；缓存失败保持内存和实时推送，后续窗口重试。意外退出可能丢失尚未保存的展示片段，重启后核对官方来源再重建；任务队列、去重与执行回执不使用这个合并窗口。

## 在线数量与维护模式

中转在电脑握手能力中声明 `clientPresence: true`，仅向所属电脑发送 `clients.presence`：

```json
{"v":1,"type":"clients.presence","hostId":"synthetic-host","generation":"synthetic-generation","onlineCount":1,"revision":1}
```

数量按有权访问该实例的真实手机/Web 连接统计，不根据资源订阅次数猜测；同一设备多个标签页分别计数。通知不包含设备身份或聊天内容。电脑仅接纳当前连接、实例代次匹配且版本递增的快照。旧中转不提供该能力时保留兼容模式。

| 模式 | 条件 | 行为 |
|---|---|---|
| 在线 | 至少一个授权客户端在线 | 索引通知合并更新，每两秒补偿核对活动 |
| 宽限 | 最后客户端离线不足五分钟 | 保持本地维护，停止设备数据推送 |
| 轻维护 | 连续五分钟无人在线 | 释放内部完整正文跟随，每十五秒核对元数据和明确任务事件 |

重新在线立即取消降频计时并恢复维护。轻维护不逐段投影正文；确认历史终态后才保存最终窗口。来源不变不重复解析，列表只增量更新变化行。降低采集强度不会停止桌面任务、消息队列或原有安全校验。

## 列表追平字段

详情展示事件先更新内存并推送，不逐帧写入 SQLite 事件表。每次连接服务进程启动生成新的展示流 epoch，序号仅在该进程内单调增长；内存最多保留 2000 条且序列化 UTF-8 总量不超过 4 MiB。旧 epoch、非法或未来游标、淘汰或删除造成的缺口均拒绝增量续接，改取完整窗口。命令占位、检查点、执行回执、提交及消息队列和题组防重复仍在确认或执行前后及时持久化，未知结果不自动重发。

响应和 `threads.event` 保留完整 `threads` 与 `revision`，增加可选字段：

- `syncing`：首次或从轻维护恢复后的追平进度，首帧仍可使用；一次追平五秒后结束转圈，未完成部分继续后台重试。
- `syncError`：固定的中文短错误，已有列表保持可用。
- `catchup`：初始或恢复基线，不将历史结果当成新完成通知。
- 行内 `notificationBaselineState`：供新手机建立完整通知基线；兼容旧手机的 `notificationState` 在基线帧仅保留待交互事项，清空历史终态标记。

元数据状态变化也推进列表版本。普通索引和流式变化不反复开启首次追平，也不重置通知基线。收到有效索引后即可显示、筛选和打开聊天；发送、停止、审批和答题仍要求当前实例的实时详情确认。

## 验证边界

运行 `npm test` 和 `npm run check:privacy`。相关测试覆盖五分钟模式边界、多标签计数、未知状态、活动恢复、迟到订阅清理、后台额度、静态文件复用、通知基线及旧代次拒绝。

合成资源测试、真实编译 Web、真实桌面与 Android/iOS 真机应分别记录。服务端快速索引回执不等同于列表完成实时追平；性能对照需同时报告首帧和追平时间。CPU 使用单核等效口径，同时报告实际处理量，避免将不同吞吐量的采样混为等负载结果。
