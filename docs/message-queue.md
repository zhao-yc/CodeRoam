# 消息排队与追加指令

“排队”是任务忙时的新消息行为，不代表所有发送都要先入队。电脑确认聊天空闲、没有待发消息或待处理操作时直接开始新一轮；手机按回执实际的 `queued` 状态显示“指令已发送”或“已加入消息队列”。空闲判断后若明确发生任务竞争才转为排队，发送超时或结果未知不自动重复入队。

排队卡片提供“编辑”：电脑先将尚未发送的消息撤回并暂停其投递，再把原文、图片和原上传附件恢复到输入框。确认恢复后清理撤回记录；点击编辑本身不会发送消息。输入框已有草稿时先提示发送或清空，不覆盖已有内容。已经开始发送或结果待核对的消息不能撤回编辑。

撤回回执丢失时，原内容仍在电脑端保留为“已撤回，可继续编辑”，再次点击编辑可恢复，且不会自动发送，也不会阻塞其他排队消息。附件过期或恢复失败时保留原记录；新编辑能力通过实时快照声明，旧连接服务不显示编辑入口。

设置页提供“新消息默认发送方式”，可选择“排队”或“追加指令”，初始为排队。排队后，仍可通过消息卡片手动追加到当前任务。该偏好仅保存在当前设备，刷新后保留；只影响之后发送的新消息，不会自动追加、取消或重排已经入队的消息。选择追加指令时，运行中的新消息进入当前任务，空闲时仍开始新一轮。聊天输入框上方不再常驻显示排队说明。

- 连接服务支持排队时，输入框发送先保存到电脑连接服务队列。运行中的任务继续执行，空闲后按顺序开始下一轮，不自动追加到当前任务。
- 排队卡片显示原文及图片、附件数量。点击“追加到当前任务”才将该条消息提交给当前任务；成功后从队列移除，不会再发送一次。任务已经变化时保留排队消息并提示重新同步。
- 可取消尚未发送的消息。失败或结果未知时暂停该会话的后续队列，先核对聊天记录，再移除记录并按需重新发送；移除已提交记录不会撤回桌面已经收到的消息。
- 队列存在连接服务自有 SQLite 账本中，手机切页或断开后仍可继续。连接服务重启保留等待消息，发送中的消息变为待核对，不自动重发。每个会话最多20条；只有原设备能手动追加或取消。
- 归档、永久删除成功后清理对应队列；待确认计划、审批、原生问答、离线或状态未知期间不自动发送。附件仍受上传有效期约束，过期后提示核对并重新选择。
- 协议复用 `turn.send` 白名单，通过 `queueAction: enqueue/steer/cancel` 区分队列操作；追加和取消只接收队列编号，追加还校验 `expectedTurnId`。实时快照与增量携带 `supportsMessageQueue` 和 `queuedMessages`。
- 旧连接服务尚不支持排队时，空闲发送保持可用；运行中提示升级，不会偷偷改用追加指令。中转沿用既有发送白名单，无需新增任意执行入口。
