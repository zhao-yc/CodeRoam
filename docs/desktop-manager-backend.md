# 桌面管理端的本机接口

Electron 主进程创建托盘后启动 Node.js 24 守护。父子两级 IPC 断开时停止接收新任务并限时退出。关闭窗口时托盘和手机连接继续运行。明确退出客户端时，主进程先通过认证接口排空并停止桥接，再关闭与当前托管配置匹配的守护。下次打开可恢复同一个托管服务。

## 连接与权限

`service-supervisor.mjs --desktop-owned --config <worker.json>` 在原 `runDirectory` 创建 `management.json`。端点使用随机命名管道（Windows）或当前用户专属目录内的 Unix 套接字（Mac/Linux），每次守护启动重新生成能力令牌。该接口不经过中转，也不加入手机协议白名单。

Windows 的端点、配置备份和配置临时文件在创建时赋予当前用户、系统和管理员的私有 ACL；Unix 文件权限为 `0600`，套接字目录为当前用户所有的 `0700` 目录。管理客户端重新检查端点文件权限、托管路径摘要和托管文件修订，拒绝跨服务连接。令牌仅由 Electron 主进程读取，不返回网页界面。

客户端模块 `management-client.mjs` 仅使用 Node 内置模块。`connectManagement(workerConfigPath).request(method, params)` 每次调用使用一条短连接；同时最多接受 16 条连接，请求上限 64 KiB，响应上限 256 KiB。请求和响应均包含本次编号，响应另外核对守护 PID。

## 方法

| 方法 | 参数 | 返回内容 |
| --- | --- | --- |
| `status` | 空对象 | 运行与连接状态、桥接及守护 PID、版本、生效和保存的配置修订、实例展示状态 |
| `config.read` | 空对象 | 允许编辑的配置投影、保存修订、是否已配置令牌 |
| `config.save` | `expectedRevision`、`values` | 新的安全配置投影；保存不会自动重启 |
| `logs.read` | 可选 `limit`，1～200 | 已知生命周期事件的中文说明与时间，不读取会话或 stdout |
| `service.restart` | 空对象 | 受控重启的接纳结果；管理界面随后重新读取状态 |

只开放 `label`、`relayUrl`、`multiInstance` 和 `newConversationSettingsCache`。缓存默认有效期两小时、最多 64 项；有效期允许 0～24 小时，数量允许 1～512 项。有效期为零时关闭已完成结果的复用，并保留在途同键读取合并。

保存支持允许字段的部分更新，保留原配置中的令牌、主机编号及其他未知字段。名称为 1～80 字符，跨网络中转使用 `wss:`，地址不能包含凭据、查询参数或片段。写入使用修订比较、排他锁、同目录私有原字节备份及原子替换，旧界面不能覆盖较新的保存。

## 生效与受控重启

第一版的配置保存只改变磁盘版本，`status.restartRequired` 明确表示是否仍需重启。新聊天缓存参数在桥接实例构建时读取，配置更新在受控重启后生效。

重启由父子进程专用 IPC 完成：先暂停新手机写入、附件上传和新队列领取，逐实例检查当前请求、自有命令账本和正在运行的提交任务。有在途操作就取消排空并恢复原队列，管理界面收到忙碌错误。空闲时请求桥接正常关闭，原守护启动下一份桥接并读取已保存配置。关闭过程已开始后若失败，子进程明确退出并由守护恢复，不能停留在永久禁止写入的半关闭状态。

所有重启都保留原操作账本和未知结果保护，不重放手机消息，也不修改 Codex 安装、登录文件或原生桌面数据库。登录启动由 Electron 主进程管理。旧系统服务和旧登录项由新版桌面程序核验后接管。

真实 Windows 和 Mac 的安装、管道权限、系统服务及窗口生命周期需要分别验收；合成管道和进程测试不能代替另一系统的实机证据。
