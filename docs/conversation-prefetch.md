# 聊天内容静默预加载

手机应用在前台并保持连接时，监听已授权在线电脑的最近聊天列表。收到新的正文、执行进度、完成、失败或待交互状态后，提前准备对应聊天的最近正文和操作摘要。手机与电脑保持当前页面，预加载不会标记聊天已读，也不会发送、停止、回答或审批任务。

点击聊天时复用现有本地缓存首屏，随后订阅实时内容。缓存仍是纯展示数据；得到有效实时快照前不启用写操作。更早历史、图片原文件及附件继续按需读取。旧聊天更新进入最近列表后也会参与预加载，不在连接时下载全部历史。

列表摘要的可选 `contentRevision` 标记可缓存内容的变化，不包含正文或凭据。正文流式变化合并推送，完成、失败及待交互状态及时推送。手机通过既有只读接口 `thread.history` 发送 `{ threadId, view: 'prefetch' }`，取得 `{ snapshot, contentRevision }`；该视图只读取已有实时快照或已保存历史，不建立、取消或复用手机详情订阅。

全局最多两个预加载请求，同一聊天普通流式更新最多每秒读取一次；终态和待交互更新优先，在途更新合并后补取。用户点击不等待预加载队列。首次连接只预热执行中、未读、待交互或已有旧缓存的聊天，其余聊天在新出现或内容变化后预加载。旧桥接未提供版本标记时继续原有打开流程；读取和存储失败静默降级并退避。

沿用本地缓存最多 20 个聊天、总计 3 MiB、单聊天 512 KiB 的边界，预加载保留已经加载的额外历史。后台、断线、重新配对、授权撤回、实例换代、归档和删除会废弃相关在途结果；旧响应不能覆盖用户打开后的实时内容，也不能恢复已清理的缓存。

自动化使用合成会话覆盖内容版本、流式合并、并发、跨电脑隔离、缓存恢复与清理。Web 编译、浏览器、公网版本、真实桌面和手机真机验收分别记录。
