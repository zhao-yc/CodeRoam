# 手机与桌面共用原生新建草稿

手机展开新建输入区、选定电脑和项目后，只读项目模型及权限选项，文字和选项先保存在手机草稿中。点击发送才调用电脑原有的新聊天动作，或复用已打开且核对过的草稿。正式聊天由原桌面提交首条消息时创建。

## 原生上下文

- 电脑连接服务把公开草稿编号绑定到设备、项目、桌面实例、页面和原生草稿编号。手机只能提交已保存项目编号，不能指定目录、程序、调试地址或代码。
- 编辑时，模型及权限菜单使用现有的 `thread.create.settings` 和 `thread.create.permissions` 只读接口。手机选项在发送前保留为本地意图。发送时以原生草稿的模型与权限能力为准，应用明确选过的设置并核对实际结果。电脑草稿为完整访问时，需要手机明确选择并确认。
- 打开草稿后，电脑端的变化通过草稿事件同步。发送前回读实际设置和版本，选项不符时保留手机草稿。收起输入区停止检查，保留已打开的原生草稿。
- 首条消息从绑定的原生草稿提交，正式会话编号返回后进入普通聊天订阅。PC 先提交时，手机跳转到对应聊天，保留手机未发送的内容，不自动追加。
- 手机文字不实时写入 PC 输入框。PC 草稿已有未发送内容时拒绝覆盖；完整访问沿用显式确认和原生策略限制。

## 白名单协议

`projects.list` 增加 `supportsNativeNewDraft`。客户端没有该能力时提示更新，不回退到旧的新建通道。

| 接口 | 分类 | 主要参数 |
| --- | --- | --- |
| `thread.draft.open` | 写入并去重 | `projectId` |
| `thread.draft.read` | 只读并恢复订阅 | `draftId` |
| `thread.draft.update` | 写入并去重 | `draftId`、`expectedRevision`、`changes`、`confirmedFullAccess` |
| `thread.draft.send` | 写入并去重 | `draftId`、`expectedRevision`、`text`、`images`、`attachments` |
| `thread.draft.unwatch` | 取消观察 | `draftId` |

公开快照包含 `draftId`、`projectId`、`revision`、`status`、`settings`、`models`、`permissions` 和 `hasDesktopText`；正式会话生成后补充 `threadId`。状态为 `ready`、`detached` 或 `promoted`。原生编号、窗口、进程、端点和工作目录不进入快照。

`thread.draft.changed` 事件仅发给已授权并订阅该草稿的设备。实例代次变化后丢弃旧事件。附件分片接口的 `draftId` 与 `threadId` 必须二选一，草稿附件不能跨设备、项目或会话使用。

## 并发与恢复

- 设置与发送必须携带读取时的修订。PC 改动、项目切换、离开草稿或草稿已发送后拒绝旧写入。
- 新建、设置、发送共用原有操作账本。结果未知时保留原命令编号，只核对、不自动重放；重新打开页面不能绕过未知写保护。
- 正式会话只在原生提交流程中产生；获得编号不等同于消息已确认，未知提交不能靠再次创建消除。
- 关闭电脑连接服务或手机取消订阅后，在途旧读取不能重新建立观察。
- 桥接重启丢失内存绑定时，仅在持久账本的原指纹与唯一已保存项目的 `thread.draft.open` 完全匹配后，关闭失效的新建连接并保留原检查点。手机保留输入，下一次打开由用户点击发送触发。未知设置更新和发送仍保留保护。

模拟测试、Web 编译、公网测试、Windows 原生桌面、Mac 原生桌面和手机真机分别记录，不能用其中一种替代其他验收。
