# 会话详情本地缓存

已同步的会话会在当前设备保存最近正文与已加载的历史。进入详情时直接从内存索引取副本，桌面导航和实时订阅继续在后台完成。当前订阅确认后，以实时内容接续展示。同步失败时保留缓存并提供重试，首次打开或缓存不可用时沿用联网加载。

缓存只用于展示，不恢复运行状态、审批、待回答问题或写操作权限。图片和附件文件仍按原流程读取，草稿保存方式不变。电脑未返回有效实时快照前不能发送、停止或审批。

正文与额外历史分开保存，最新快照替换旧正文，同编号消息以电脑新值为准。恢复历史时不使用旧分页游标，而是从最早保留的消息编号继续读取。用户阅读历史时保留可见消息位置，跟随最新消息时继续跟随。

缓存按配对命名空间、电脑和会话隔离。默认最多保存最近访问或同步的 20 个会话，总计 3 MiB、单会话 512 KiB，大小按序列化字符串长度的两倍保守计算。超限优先移除最早完整消息，再淘汰最久未访问的会话，不截断消息正文。裁剪最近窗口后弃用原版本，下一次同步重新核对基线。

Android 和 iOS 将缓存保存在 App 私有 SQLite 数据库，Web 使用同源 IndexedDB。启动只恢复会话索引。冷打开时读取选中聊天尾部最多八条完整消息，首屏后只补齐该聊天尚未读入的正文和已加载历史。热打开直接使用内存窗口。详情按视口估算首批挂载的条目数量，随后分批补齐，补齐时保留可见消息位置。

流式更新以 500 毫秒为窗口合并，同一事务仅写入变化的消息、顺序和会话版本。首屏预览不携带完整窗口版本。收到增量时才按需读入对应的完整基线。旧 Storage 缓存可先用于首屏，数据库迁移提交后才移除旧键。存储不可用时保留可用内存正文，等待后续重试或联网补齐。

更换或清除配对、撤回电脑授权、确认归档或永久删除后清理相应缓存。普通离线保留缓存。清除浏览器站点数据或应用数据也会移除缓存。存储失败的日志不包含正文和原始异常。

自动化测试使用合成会话验证缓存恢复、后台刷新、历史去重、配对隔离、容量淘汰、清理与存储异常。Web 编译、浏览器、公网访问、真实电脑和 Android/iOS 真机验收分别记录。
