# 聊天数据与列表摘要

手机每次打开聊天都向 PC 守护进程订阅当前数据。正文仅用于当前页面渲染，退出详情后释放。重新打开时重新读取电脑，短暂断线时保留当前画面，重连后核对当前版本并继续接收更新。

守护进程为每个桌面实例持续维护最近 20 个聊天。有已核验的桌面 IPC 状态时跟随实时变化，其他聊天在索引和历史来源版本变化时更新。最近窗口写入守护进程自己的 SQLite，重启后核对来源再复用。中转只转发正文。

## 首屏与实时订阅

新版中转声明 `conversationPreview` 能力。手机对没有当前基线的 `thread.watch` 请求提交独立 `previewId`。守护进程可以先通过定向的 `thread.preview` 事件返回当前展示窗口，同时完成桌面切换和实时读取。实时读取先完成时直接返回快照。

最终回执确认实时状态和订阅游标。同一请求已经发送的正文可作为基线，同版本只回元数据，变化时补差异。预览不携带可执行审批、问题或图片读取权限，发送、停止和审批要求当前会话的有效实时订阅回执。缺帧或基线失效时重新请求完整窗口。

从列表、通知或直达链接进入详情只读取并订阅后台状态，不切换电脑端当前显示的聊天。已有可用所有者时直接跟随实时更新；尚未加载的聊天保留历史浏览及草稿，不自动打开桌面页面。需要加载桌面聊天时，由用户点击右上角菜单的“重新同步”；该操作会打开对应桌面聊天、确认已读并重新取得状态。断线恢复、页面重新可见和失败重试不会自动重放桌面导航。新建聊天首次发送仍沿用原有加载流程。

重连只恢复当前订阅。旧中转或守护进程通过普通 `thread.watch` 返回完整快照。手机不订阅其他聊天的正文，也不随列表版本变化请求正文。归档、删除、撤权和实例换代使旧帧失效。

## 手机持久数据

列表继续在 Android、iOS 的私有 SQLite 和 Web 的 IndexedDB 中保存电脑显示信息、聊天编号、标题、项目路径和更新时间。每台电脑最多 50 条，每个配对最多 500 条、合计 1 MiB。冷启动并行恢复摘要和连接中转，收到实时列表后按行替换。

完全离线时可以搜索、分组和筛选列表摘要，查看正文需要连接电脑。草稿与操作核对记录继续使用各自的存储。旧版正文在升级后异步清理，保留列表摘要和其他数据，数据库事务成功后再移除旧 Storage 正文键。失败时下次返回前台重试，不阻塞联网。

自动化覆盖首屏与实时确认、流式增量、缺帧补齐、快速切换、实例换代、撤权和旧正文清理。Web 编译、浏览器、公网版本、真实电脑和手机真机验收分别记录。
