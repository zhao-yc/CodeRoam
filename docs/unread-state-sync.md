# 会话未读状态同步

手机列表的未读圆点来自桌面原生目录的 `isUnread`，由桥接转换为 `hasUnreadTurn`。任务执行中继续显示加载状态，空闲或状态未知且未读时显示绿色圆点。读取列表不应导航桌面或主动标记已读。

Windows 后台桥接不依赖聊天进程注入的管道环境变量。帮助程序先核对原生管道的安装路径和进程身份，再取得当前会话 IPC 的服务进程；原生工具管道必须与该进程一致。多实例、不同配置目录或启动顺序不能使桥接串到另一套桌面。

IPC 暂不可用时保留已验证的显式管道和单实例兼容；存在多个候选且无法唯一对应时返回不可用，保持未读状态未知。不会读取鉴权文件、修改桌面安装文件或写入桌面数据库。

查看手机详情与桌面导航分离。Windows 服务声明 `supportsReadState` 后，手机只在正文已挂载、页面可见且本次订阅确认后调用 `thread.read`。连接服务核对设备订阅及原实例身份，通过 `set_thread_read_state` 标记已读，不调用桌面导航。原生回执中的聊天编号、本机来源和已读值必须匹配，之后才清除未读状态；历史浏览不需要执行所有者。页面隐藏、切换及迟到回执不能清除新目标的未读。旧服务及尚未支持独立原生确认的平台不声明此能力。

右上角“重新同步”仍可显式切换并加载桌面聊天，再复用同一已读确认实现。目录刷新在后台校准；已有目录请求很慢或刷新失败时，不撤销已经确认的已读，也不因此取消订阅。

目录查询期间如果出现新的已读确认，则丢弃旧查询结果并安排新查询，避免迟到结果恢复已经清除的未读圆点。连接失效及关闭后的旧回执也不重新发布未读状态。真正的原生调用超时使用 `DESKTOP_NATIVE_TIMEOUT`，提示明确区分聊天切换确认、已读状态确认与目录刷新阶段。

回归覆盖无聊天环境变量的多实例选择、与环境变量冲突时的 IPC 优先级、对应实例缺失或重复、单实例兼容及非法管道。真实桌面同步、公网 Web 与真机验收分别记录。
