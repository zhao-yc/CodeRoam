# 永久删除对话

详情菜单在“归档”下方提供“永久删除”。必须依次确认删除范围和不可恢复提示，第二次确认前不会发送停止或删除请求。切换电脑、会话或离开页面会使旧确认失效。

第二次确认的左侧是红色“永久删除”，右侧是“取消”，正文不显示聊天名称。提交后不显示全屏等待层，详情页提示“正在删除，可以返回”。用户可以返回列表、打开其他聊天、切换电脑或将手机切到后台；这些行为不撤销电脑已接收的删除任务。

删除请求通过首次目标校验后，连接服务立即入账并保留内部订阅，排队和执行不再依赖手机页面订阅。仍持续检查原桌面身份、任务状态及关联范围，结束后释放内部订阅。电脑连接服务退出或重启时不自动恢复删除动作，只恢复结果核对。

手机应用级服务按配对、电脑、聊天及原请求编号保存删除任务，不保存聊天名称或正文。列表显示“删除中”或“结果待核对”，并提供独立任务入口；目标未包含在当前列表时也可以核对。受影响聊天暂时只读，其他聊天可正常使用。成功回执由应用服务统一清理，重复回执不会重复提示；只有用户仍在被删除聊天页面时才返回列表，不导航其他页面。

连接服务先沿原生索引的附属关系只读枚举子对话，包含已归档子对话；普通分叉不属于该范围。有原桌面所有者且仍在执行的任务先通过原桌面停止，再等待空闲快照。不自动回答审批。提交前重新核对原所有者、删除范围和运行状态。

Windows 删除复用原桌面列表右键菜单中绑定到该行的永久删除动作，以及桌面原有确认框。连接服务按固定菜单动作标识打开确认框，不依赖浮动菜单的屏幕位置、语言或 Windows 可访问性树，也不需要人工运行电脑操作技能。界面连接必须来自已验证的原桌面进程和本机回环端口；不主动开启调试端口。确认框必须携带匹配的会话编号和电脑编号，仅标题相同不能确认。没有相应能力时提示在电脑端处理，不操作数据库或启动第二个写入者。

桌面刚新建的对话可能仍使用 `client-new-thread:…` 作为侧栏键。连接服务通过该行组件与 DOM 属性一致的绑定核对正式会话编号和电脑编号，不按标题猜测。已渲染但滚出视口的目标会先滚动到可操作位置，再重新核对编号与菜单提供者；多个窗口同时匹配、菜单读取期间目标变化或动作定义不兼容时停止操作。

连接服务在自己的数据目录保存 `delete-ui-diagnostics.jsonl`；多实例各自记录。诊断只包含请求编号、阶段、匹配数量及错误码，不记录标题、消息正文或令牌。可据此区分没有目标行、临时编号已匹配、目标位于视口之外以及多个窗口重复匹配。

`thread.delete` 是白名单写接口，仅接受 `threadId`。成功回执包含 `threadId`、`deleted: true` 和 `deletedThreadIds`。只有原生索引确认整个范围都已删除后，才清理手机列表、草稿、历史和桥接事件缓存；操作账本继续保留去重回执。项目文件不在删除范围内。

断线、超时和部分删除保留待核对编号，手机刷新后仍然保留。点击“核对删除结果”只查询原命令。连接服务根据原请求指纹和已保存的完整范围只读核对；所有目标均不存在时才确认成功，归档和部分删除不能冒充完成。任何核对都不重放停止或删除。

恢复前台、重新连接或电脑恢复在线后，应用自动向原电脑核对原命令，不改变当前选中的电脑。仍在运行的命令每三秒只读查询一次；未知或未找到的命令保留核对入口，不持续轮询或自动重新提交。旧版待核对编号仅在恢复原配对时迁移，新配对不继承旧删除保护。

模拟测试、Web 构建、公网访问、真实桌面和 Android/iOS 真机验收分别记录。真实桌面测试只使用可丢弃的合成对话。
