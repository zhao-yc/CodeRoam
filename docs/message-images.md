# 聊天图片预览与发送

用户发出的图片与助手回复的图片统一按需分片读取，单张原图上限为 12 MiB，每条消息最多三张。手机每次读取一张图片的一个分片，避免超过中转单条消息 2 MiB 的限制。图片不进入持久缓存；只有当前电脑、聊天和有效订阅一致时才读取，切换目标、断线或卸载后丢弃旧回执。

`large` 仅控制助手图片的展示尺寸，不决定读取上限。旧版不带图片和分片编号的整张读取接口保留 320 KiB 限制，以保持其传输体积边界。

手机发送仍使用内嵌图片，每张最多 320 KiB、最长边 1600 像素，图片与文件合计最多三个。预览上限提高不等于上传上限提高。选择相册或拍照时先获取原图，避免系统预压缩与发送压缩叠加。

发送前，大小和尺寸均合规的 JPEG、PNG 原样保留，包括透明 PNG。必须压缩时，Web 在同一尺寸依次尝试 92%、85%、75%、65% 的 JPEG 质量；App 依次尝试 90%、80%、70%。同尺寸全部超预算后，才将宽高缩小为上一档的 80%，并重新从高质量尝试；每次均从原图处理，避免累计重压。质量数值是编码器参数，不代表文件缩小比例。

测试使用合成数据验证 12 MiB 预览边界、分片完整性、切换目标隔离、原图直通、压缩阶梯和上传预算。模拟 App 接口与 Web 构建不能替代 Android、iOS 真机上的图片清晰度验收。
