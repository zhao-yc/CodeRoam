# 提交任务与执行记录

电脑连接服务在自己的 SQLite 账本中保存提交任务，不写入 Codex 原有数据库。每个实例按提交顺序串行执行，不同实例可以并行。手机收到持久化入队回执后可以切页或断开，已经接纳的任务继续执行。

## 手机交互

电脑筛选栏下方显示提交顺序、所属电脑、当前步骤和结果，默认最多三项，可展开查看。新聊天先把附件完整上传，再由守护进程创建聊天、应用模型与权限选择、绑定附件并发送首条消息。确认入队后收起输入区，完成后可以点击进入聊天，不会自动跳走。

成功以操作确认生效为准，不等待模型回答结束。成功项按服务端完成时间显示五秒，随后仍可在执行记录中查看。失败和结果待核对项保留，关闭展示不会恢复执行。设置区分别显示已确认值和待执行选择。

## 执行与恢复

所有桌面业务写操作经过统一执行器，包括停止、审批与问答。读取、上传和任务管理不占用执行槽。原有忙时消息队列仍可使用，自动投递也进入统一执行器；等待会话空闲不占住提交任务的执行槽。

任何任务失败或结果未知都会暂停整个实例，后续停止、审批也会等待，其他实例不受影响。只允许取消尚未开始的任务。明确失败可人工继续；未知操作先只读核对，无法确认时须明确确认已在电脑核对并跳过，历史保留结果未确认的说明。不会自动重发写操作。

守护进程重启后保留等待任务；在途任务转为待核对并暂停。组合任务按步骤保存独立命令编号和成功检查点。中间步骤只读核对成功后等待人工继续，只执行尚未提交的步骤；最后一步核对成功才收口整个任务。

后台任务使用独立会话租约，手机退出详情不撤销执行上下文。任务执行前继续核验原实例身份、原生修订、权限及首条消息保护。进行中和待核对任务持有的附件不受普通临时文件回收影响。

## 协议与保留

`tasks.submit` 只接收受限的原业务命令或组合新建任务；`tasks.list` 查询当前任务、分页历史或指定编号；`tasks.watch/unwatch` 订阅状态；`tasks.control` 提供取消、关闭、核对、继续和确认跳过。`tasks.changed` 仅向原提交设备的有效订阅推送，并核验电脑授权与实例代次。

同设备同编号按内容指纹去重，回执丢失只查询原编号。展示事件与历史不携带原执行参数、正文或图片；需要恢复编辑等业务结果时定向查询原任务。历史保留最近三十天且最多一千条已结束记录；进行中和待核对任务不自动清理，必要去重键继续保留。

模拟测试、Web 编译、公网访问、真实桌面和 Android/iOS 真机验收分别记录。
