# 会话权限选择

现有会话和新建会话的手机端权限菜单提供「请求批准」「帮我批准」「完全访问权限」，名称和说明与桌面一致。已有只读权限仍可同步。每次切入完全访问先确认，取消不提交；新建选择只属于当前电脑和项目草稿，完成发送后清除，不修改全局配置。自定义和缺失权限分别显示自定义、未同步。

新建输入区展开并确定电脑、项目后，自动读取该项目配置中的默认权限，无须打开权限菜单。切换电脑或项目、重新展开和恢复连接时重新读取；收起后在途结果作废，同一目标的并发读取合并。菜单复用已加载结果，失败显示未同步并可重新读取。草稿中的手动选择优先显示；读取默认值不会写入草稿、创建会话或修改电脑权限，即使默认是完整访问也不视为用户确认。首条消息仍按原有流程跟随电脑配置，手动选择才应用至新会话。

## 原生接口与同步

- 新增只读接口 `thread.permissions.read`、`thread.create.permissions`，返回模式、权限版本、可选项和禁用原因；项目读取只接受已保存项目编号。
- 新增写接口 `thread.permissions.update`，只接受会话编号、固定模式、预期版本及完整访问确认标记。模型设置接口仍拒绝原始权限字段。
- 桥接通过原生 `config/read`、`configRequirements/read`、`permissionProfile/list` 读取能力，只将筛选后的选项传给手机；新旧审查字段分别兼容 auto_review、guardian_subagent。
- 切换使用原所有者的 `thread-follower-update-thread-settings` v2，只发送固定内置档案和对应审批设置，不修改安装、鉴权或原桌面数据库。
- 更新前刷新并核对版本，更新后回读。原生选择和最终沙箱可能分阶段广播，确认阶段最多重取五次快照，不重发写请求。超时保留未知结果，核对原请求指纹及桌面最终模式后才解除待核对锁。
- 运行中保存下一轮权限，并通过原生能力同步当前轮次审查方式；不自动回答既有审批。历史浏览、断线或能力读取失败时不能切换。权限只读模式仍可正常聊天。
- 新建在原桌面接管、执行设置应用后，先应用并回读所选权限，再上传附件及发送首条消息；失败保留草稿和空会话编号，未知结果先核对。

## 本次验收

- 隔离交付源码执行全套 Node.js 回归通过，覆盖四种映射、能力限制、版本冲突、确认取消、目标切换、幂等、未知结果核对，以及新建失败重试和草稿隔离。
- 真实桌面专用空会话：四种权限均完成切换及真实回读，验收后恢复原模式。没有向业务会话发送消息，也没有执行模型任务或文件命令。
- ego lite 使用回环合成服务验证菜单四项、自动审查切换及增量同步、完整访问取消与确认、新建只读选择。取消没有新增写请求；新建选择没有发送权限写请求。390 像素视口检查浮层边界，截图和虚构配置仅留本地。
- HBuilderX 5.34 使用隔离编译副本及本项目已有本地 AppID，公开清单仍为空 AppID。Web 导出通过；Android 资源导出通过。额外执行 Android 完整 Kotlin 编译时发现既有 annotations.uts 的正则捕获组可空调用，用户授权后仅补空值兜底，未改变注释解析语义，注释回归 15 项通过。原生完整编译继续暴露既有的 uni.hideKeyboard API 与问答监听匿名函数默认参数兼容错误，尚未通过；权限菜单事件已改为显式布尔回调。已有的新建组件样式还提示百分比 max-width、属性选择器不受原生支持。
- 本次没有发布 APK 或部署公网。Android/iOS 真机、运行中真实审批及实际沙箱执行边界仍需设备和专用任务验收；空会话切换与模拟测试不能代替这些证据。

复现使用 HBuilderX CLI：`publish web --project <工程绝对路径>`、`publish app-android --project <工程绝对路径> --type appResource`、`launch app-android --project <工程绝对路径> --compile true --ui true`。开源清单中的空 AppID 需先在本机私有配置或隔离副本补齐。界面模式只返回命令下发时，用同一 CLI 的 `--ui false` 获取纯编译日志。
