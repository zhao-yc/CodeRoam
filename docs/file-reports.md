# 任务报告的修改文件汇总

明确标记为最终回复的任务报告下方展示修改文件卡片：文件总数、增删行数、前三个文件，以及完整列表入口。点击文件可直接打开该文件的差异；详情面板支持逐文件展开、独立滚动、全屏和关闭，关闭后保留聊天阅读位置。

行数来自 PC Codex 自带的文件转换器、差异解析器与汇总函数。桥接和手机不另行统计增删行数，也不使用当前 Git 工作区冒充历史任务。每份报告只包含前一份最终回复之后、这份回复之前成功完成的文件修改，同一文件多次修改合并列出并保留修改顺序。无修改时隐藏卡片；历史缺失、格式不兼容或差异过大时明确提示。

## 只读数据接口

沿用 `thread.history` 白名单方法，增加 `view: "file-report"` 与 `reportId` 参数。只读返回汇总和不含正文的文件清单；传入响应中签发的 `fileId` 才返回对应文件差异。拒绝路径、脚本、模块地址及多余参数，读取前后均核对订阅和会话所有者，切换电脑或会话后丢弃迟到结果。

最近消息窗口不完整时，从桌面历史投影中按报告编号读取完整轮次，继续遵守分叉会话的继承边界；旧日志使用现有受限只读入口。PC 端差异保存在有界运行内存中，不进入聊天快照或操作账本。手机端将已经读取过的文件汇总和代码差异缓存在当前设备，再次打开聊天或差异面板时先显示缓存，实时订阅就绪后后台更新。缓存按配对、电脑、聊天、报告及报告版本隔离；报告版本变化会清除旧差异，未打开的文件仍按需读取。

手机文件缓存独立限额为 1 MiB、最多 40 份报告，单份最多 256 KiB；超限时淘汰旧文件差异和最久未访问的报告，不截断代码。存储不可用时保留联网读取能力；更换或清除配对、撤回电脑授权、归档或永久删除聊天时，与正文缓存一起清理。

当前原生统计接入支持已审核资源版本的 Windows Codex，包括数字分块资源的桌面版。普通启动也可在隔离线程调用原生算法，不依赖页面调试通道；保留旧版资源布局与调试通道兼容。只读取本机安装包并核对完整模块 SHA256，再按固定范围提取纯计算定义，不启动原模块、不修改安装包。未知版本不执行未经审核的代码。

备用模块定位明确区分“未找到兼容模块”和“多个匹配”；手机端也将旧服务的“原生模块不唯一”转换为可理解的更新指引。未支持的普通启动桌面不声明 `supportsFileReports`。Web 编译、合成浏览器验收、真实桌面读取和手机真机验收分别记录。
